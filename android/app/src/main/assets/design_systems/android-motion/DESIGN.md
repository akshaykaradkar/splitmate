# Android Motion Design System

## Overview

The Android Motion design system is a comprehensive, system-wide motion framework that bridges physical realism and digital software. It is rooted in **tactile physics**, **gestural responsiveness**, and **spatial continuity**. It ensures that every digital interaction feels connected, responsive, and alive, giving users direct, physical control over their interface.

The framework is built on three core pillars:

1. **Tactile Physics**: Movements follow intuitive physical laws. UI elements have simulated mass, momentum, friction, and springy elasticity. The system prioritizes natural spring equations over rigid bezier-curve timelines, allowing animations to be interrupted mid-flight, absorb user momentum, and stretch dynamically.
2. **Spatial Continuity**: The user interface operates in an interactive 3D environment along a strict Z-axis spatial model. Surfaces do not abruptly appear or disappear; they lift, expand, morph, and slide. When launching an app, the launcher icon morphs into the expanding app canvas, guiding the user's eye and preserving cognitive focus.
3. **Adaptive Responsiveness**: Motion reacts instantly to gesture velocity and direction. Swiping to dismiss, rubber-band overscrolling, dragging keyguard sliders (the Bouncer), and collapsing notification panels feel directly connected to the user's hand, establishing an elegant, real-time dialogue with the device.

## Colors

The Android Motion color system is powered by a dynamic, tone-based mapping model. It translates core brand reference hues (`{colors.ref-palette-*}`) into highly semantic system color tokens (`{colors.sys-color-*}`). These system tokens automatically resolve to complementary light and dark theme values, maintaining high contrast and accessibility.

Under motion, color behaves with organic activity:

- **Dynamic Ripple Feedback**: Touch actions trigger an expanding ink ripple that starts from the exact coordinates of contact. The ripple spreads outward, fading smoothly, and is colored with high-contrast on-surface tokens (such as `{colors.sys-color-on-surface}` or `{colors.sys-color-on-primary}`).
- **Surface Elevation Tinting**: Instead of relying on static, heavy drop shadows, surfaces signify elevation and depth dynamically. As elements lift (such as active cards or dragging bottom sheets), they receive a higher concentration of `{colors.sys-color-surface-tint-color}` blended directly into their background `{colors.sys-color-surface}`, making them organically lighter (in dark mode) or richer (in light mode).
- **Container Color Morphing**: When components transform (e.g., a primary container FAB morphing into an expanded card), colors smoothly interpolate along a decelerating curve to prevent visual flashing and maintain comfort.

### Color Tokens

- **Stable Canvas**: `{colors.sys-color-background}` provides a stable canvas behind scrollable content (light: `#fdfcfb`, dark: `#1f1f1f`).
- **Interactive Surfaces**: `{colors.sys-color-surface}` defines the container fill for cards, sheets, dialogs, and menus (light: `#fdfcfb`, dark: `#1f1f1f`).
- **Functional Accents**:
  - Primary Accent: `{colors.sys-color-primary}` (light: `#0b57d0`, dark: `#a8c7fa`)
  - Secondary Accent: `{colors.sys-color-secondary}` (light: `#00639b`, dark: `#7fcfff`)
  - Tertiary Accent: `{colors.sys-color-tertiary}` (light: `#146c2e`, dark: `#6dd58c`)
- **Containers**:
  - Primary Container: `{colors.sys-color-primary-container}` (light: `#d3e3fd`, dark: `#0842a0`)
  - Secondary Container: `{colors.sys-color-secondary-container}` (light: `#c2e7ff`, dark: `#004a77`)
  - Tertiary Container: `{colors.sys-color-tertiary-container}` (light: `#c4eed0`, dark: `#0f5223`)
- **Utility and Boundaries**:
  - Outline: `{colors.sys-color-outline}` defines subtle boundaries for un-elevated elements (light: `#747775`, dark: `#8e918f`).

## Typography

Android Motion utilizes a dual-font structure:

1. **Google Sans**: Used for expressive displays, headlines, and major titles. Its rounded, friendly geometric shape defines the brand's premium identity.
2. **Google Sans Text**: Optimized for smaller body copy, descriptions, and utilitarian labels. It has slightly increased tracking and line heights to maximize readability.

### Typography in Motion

- **Avoid Direct Font-Size Animation**: Animating CSS `font-size` directly forces layout recalculation on every frame, degrading performance and causing text to jitter. Instead, render text at its destination typescale (such as `{typography.title-large}` or `{typography.display-small}`) and scale it up or down using 2D transform matrices (`transform: scale()`) synchronized with container expansions.
- **Cross-Scaling Text Reflow**: During shared element transitions (e.g., list item titles expanding into detail headers), transition text from `{typography.title-medium}` to `{typography.title-large}` by animating their bounding boxes and smoothly fading their cross-scaled states.
- **Text Stability**: Lock letter spacing (e.g., `{typography.body-small}` or `{typography.label-medium-tracking}`) and weight values during transition states to prevent sudden horizontal reflow jumps.

### Typography Levels

- **Display**: For short, highly expressive text:
  - `{typography.display-large}`: 3.6rem / 4rem Google Sans
  - `{typography.display-medium}`: 2.8rem / 3.3rem Google Sans
  - `{typography.display-small}`: 2.3rem / 2.8rem Google Sans
- **Headline**: For structured page and content headers:
  - `{typography.headline-large}`: 2rem / 2.5rem Google Sans
  - `{typography.headline-medium}`: 1.8rem / 2.3rem Google Sans
  - `{typography.headline-small}`: 1.5rem / 2rem Google Sans
- **Title**: For navigational and secondary headers:
  - `{typography.title-large}`: 1.4rem / 1.8rem Google Sans
  - `{typography.title-medium}`: 500, 1rem / 1.5rem Google Sans Text
  - `{typography.title-small}`: 500, 0.9rem / 1.3rem Google Sans Text
- **Body**: For readable paragraphs and lists:
  - `{typography.body-large}`: 1rem / 1.5rem Google Sans Text
  - `{typography.body-medium}`: 0.9rem / 1.3rem Google Sans Text
  - `{typography.body-small}`: 0.8rem / 1rem Google Sans Text
- **Label**: For buttons, captions, and micro-metadata:
  - `{typography.label-large}`: 500, 0.9rem / 1.3rem Google Sans Text
  - `{typography.label-medium}`: 500, 0.8rem / 1rem Google Sans Text
  - `{typography.label-small}`: 500, 0.7rem / 1rem Google Sans Text

## Layout

The layout system is founded on a strict **8dp grid-based spacing model**, with a **4dp half-step** for dense micro-adjustments, ensuring vertical and horizontal rhythm.

In Android Motion, layout structures are interactive and elastic, adhering to physical motion rules:

- **Overscroll Stretch \& Rubber-Banding**: Scroll containers (lists, grids, scrollable views) do not hit a static wall when reaching boundaries. If swiped past limits, they execute an elastic rubber-band stretch. This is governed by a physical decay formula where displacement dampens proportionally to pull distance. Upon release, elements snap back with a light spring-loaded rebound.
- **Swipe-to-Dismiss and Spatial Reflow**: List items slide horizontally with continuous, tactile responsiveness. Once an item is dismissed, surrounding items slide vertically into place with zero-frame delay to close the gap, using a standard decelerated curve.
- **Notification Shade Pull-Down \& Sequencing**: The Quick Settings and notification shade stretches downwards on pull. The items undergo **Sequencing**: elements closer to the top slide down first, and lower cards expand with small, staggered offsets, giving the layout an organic, cascading weight.
- **Fluid Screen Reflows**: On screen rotation or fold/unfold transitions, cards and grid rows animate their widths, heights, and coordinates continuously, allowing elements to slide and reflow into their new positions rather than snapping instantly.

## Elevation \& Depth

Visual depth is expressed through a combination of **Tonal Layers** and **Dynamic Shadows** on a physical 3D Z-axis spatial model.

- **Z-Axis Spatial Layers**:
  - *Background Canvas (Z = 0)*: `{colors.sys-color-background}`. The stable layer behind all content.
  - *Default Surfaces (Z = 1-2dp)*: `{colors.sys-color-surface}`. Used for list items, standard cards, and inline components.
  - *Floating Elements (Z = 6dp)*: Used for floating action buttons (FABs), drag handles, and active filter chips.
  - *Overlays, Sheets, and Dialogs (Z = 8-12dp)*: `{colors.sys-color-surface}` with an active drop shadow using `{colors.sys-color-shadow}`, sitting on top of all content.
- **Dynamic Elevation \& Surface Tinting**: As components lift (e.g., when a user drags a list card or pulls up a bottom sheet), they dynamically blend `{colors.sys-color-surface-tint-color}` into `{colors.sys-color-surface}` to signify proximity to light, expanding the blur and offset of `{colors.sys-color-shadow}` in real-time.
- **Clipping and Masking**: Expand transitions use container transforms. Parent boundaries act as mask clips. During morphs, parent bounds clip inner nested images and texts, scaling the content within while expanding the container's corners smoothly.
- **Surface Invocation**: New panels, menus, and sheets emerge directly from the point of touch or origin, expanding outwards to illustrate clear spatial context.

## Shapes

Android Motion corner geometry conveys comfort, security, and precision. It defines how elements are contained and how boundaries morph.

### Corner Radius Tokens

- **None**: `{shapes.none}` (`0`) - used for full-screen expanded layouts.
- **Extra Small**: `{shapes.extra-small}` (`4px`) - used for tiny utility elements like tooltips and checked states.
- **Extra Small Top**: `{shapes.extra-small-top}` (`4px 4px 0 0`) - used for text fields and inputs.
- **Small**: `{shapes.small}` (`8px`) - used for action chips, tags, and small card structures.
- **Medium**: `{shapes.medium}` (`12px`) - used for floating menus, dropdowns, and card layouts.
- **Large**: `{shapes.large}` (`16px`) - used for major cards, grid cards, and sheets.
- **Large Top**: `{shapes.large-top}` (`16px 16px 0 0`) - used for bottom-anchored content card sheets.
- **Large End**: `{shapes.large-end}` (`0 16px 16px 0`) - used for navigation drawers and tabs.
- **Extra Large**: `{shapes.extra-large}` (`28px`) - used for central dialogs, pickers, and primary menus.
- **Extra Large Top**: `{shapes.extra-large-top}` (`28px 28px 0 0`) - used for bottom sheets.
- **Full**: `{shapes.full}` (`50%` or `9999px`) - used for circular FABs, badges, avatars, and check toggles.

### Shapes in Motion

- **Material Shape Morphs**: Container transitions between components with different shapes (e.g., a floating action button using `{shapes.full}` morphing into an expanded bottom sheet using `{shapes.extra-large-top}`) must animate their corner radii continuously. The corners flatten dynamically along an organic easing curve.
- **Asymmetric Morphing**: Corner radii scale independently if the expansion is asymmetrical, ensuring the shape feels elastic rather than rigid.

## Do's and Don'ts

- **Do** use spring physics (stiffness, damping ratio) for all interactive gestures (dismiss, drag, overscroll) so the animation preserves user momentum.
- **Don't** use linear or constant-velocity transitions; they feel lifeless, robotic, and highly digital.
- **Do** morph container geometries continuously (such as scaling a circular FAB to a square card) using mask clipping and corner radius interpolation.
- **Don't** perform abrupt cross-fading of elements where their visual provenance and spatial context are lost.
- **Do** animate text size by scaling its container container and applying a 2D transform to the text rather than animating the font size.
- **Don't** animate CSS `font-size` directly; it forces a layout recalculation on every single frame, causing jitter and degrading performance.
- **Do** blend `{colors.sys-color-surface-tint-color}` into `{colors.sys-color-surface}` to organically signal elevation levels.
- **Don't** rely on heavy, static, highly dark drop shadows for visual depth.
- **Do** sequence entry transitions, cascading screen elements slightly from top-to-bottom or left-to-right to guide visual reading order.
- **Don't** animate all elements on a screen simultaneously, which causes overwhelming visual chaos.
