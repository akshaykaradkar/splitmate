### `P1` — High-Value Whole-App Refinements (Dark Mode Contrast & Intent/Preview Parity)

1. **`[P1-1]` `Gm3AuroraEnergySurface` & `Gm3EnergyStatusPill` Dark Mode Surface Adaptation (`AuroraEnergySurface.kt:L74, L83, L234, L279`)**
   - **Finding**: `BUCKWHEAT_SAGE` and `AVIATION_PERIWINKLE` palettes hardcode `baseContainer = Color(0xFFF7F3EC)` and border `Color(0xFFEDE7DF)`. On `QuickExpenseScreen` (`QuickExpenseAndGuideScreens.kt:L1234-L1275`), when Dark Mode (`SplitMateTheme.isDark == true`) is enabled, the calculator hero display renders light `#FAF6F0` text inside the `#F7F3EC` cream Aurora surface, causing low contrast.
   - **Remediation**: Make `Gm3AuroraEnergySurface` and `Gm3EnergyStatusPill` dark-mode aware via `SplitMateTheme.isDark` (`Color(0xFF24201C)` base container and `Color(0xFF38322C)` border in Dark Mode).

2. **`[P1-2]` `QuickExpenseScreen` Primary `"Log & Split"` CTA Dark Mode Inversion (`QuickExpenseAndGuideScreens.kt:L1566-L1575`)**
   - **Finding**: When `canCommitSplit == true`, `ctaContainerColor` is hardcoded to `Color(0xFF23201E)` charcoal even when `isDark == true`, blending into the `#181512` dark canvas.
   - **Remediation**: When `isDark && canCommitSplit`, use `Color(0xFFD7E8B6)` (Soft Sage) with `Color(0xFF1E2F08)` text (matching the Dark Mode CTA inversion in `TripSyncAndPerspectiveSheet` and `TripHomeScreen`).

3. **`[P1-3]` `FlightExpenseReviewScreen` & `PnrExpenseReviewScreen` Outer Scaffold Chrome in Dark Mode (`FlightExpenseReviewScreen.kt:L76-L152`, `PnrExpenseReviewScreen.kt:L79-L145`)**
   - **Finding**: While keeping the physical boarding pass / IRCTC paper ticket cardstock warm cream/white is an intentional skeuomorphic choice, the outer `Scaffold` background, top bar, and bottom sticky commit bar in `FlightPassTokens` / `TactilePaperPassTokens` remain static light cream in Dark Mode.
   - **Remediation**: Make outer screen background (`ScreenBackground` / `CanvasBg`) and surrounding chrome cards dark-mode adaptive via `SplitMateTheme.isDark`.

4. **`[P1-4]` `FlightExpenseReviewScreen` Local UI Split Preview Tie-Break Order (`FlightExpenseReviewScreen.kt:L706-L718`)**
   - **Finding**: The local UI preview on `FlightExpenseReviewScreen` distributes `+₹0.01` remainder paise by `selectedMemberIds` iteration order (`index < remainder`), whereas tapping **Confirm & Split** delegates to `SplitMateMathEngine.splitEquallyZeroDrift` (which orders `payerId` first, then `memberId`).
   - **Remediation**: Delegate `splitAllocationsPaise` in `FlightExpenseReviewScreen.kt:L706-L718` directly to `SplitMateMathEngine.splitEquallyZeroDrift` so the preview and persisted Room splits always match 1:1.

5. **`[P1-5]` Register `android.intent.action.SEND` (`text/plain`) in `AndroidManifest.xml` (`AndroidManifest.xml:L46-L65`)**
   - **Finding**: `MainActivity.extractTripSyncPayloadFromIntent` (`MainActivity.kt:L79-L89`) already supports receiving shared `SM2_` text via `Intent.ACTION_SEND` (`text/plain`), but `AndroidManifest.xml` only declares `MAIN/LAUNCHER` and `VIEW` (`splitmate://trip-sync`).
   - **Remediation**: Add the `ACTION_SEND` (`text/plain`) `<intent-filter>` to `MainActivity` in `AndroidManifest.xml` so users can share a WhatsApp Sync message directly to the SplitMate app icon from Android's system Share Sheet.
