# Icons - Universal AI Detection Guide & Elements GM3 Specifications

This reference provides universal visual heuristics for detecting Icons (standalone, decorative, or interactive graphical symbols) across any UI, followed by Elements GM3 design system specifications for compliance auditing.

## Part 1: Universal AI Detection Heuristics

An **Icon** is a compact graphical vector or symbol used to visually communicate concepts, tools, actions, or product branding. Agents must detect icons based on their vector geometry, graphic isolation, and structural context, regardless of design system adherence.

### Key Visual & Geometric Heuristics

-   **Vector Geometry & Isolation**: Look for isolated, monochromatic or branded vector graphics (e.g., silhouettes, glyphs, or outline symbols) that convey meaning without relying on adjacent text. They appear at small visual scales (typically 18dp to 24dp).
-   **Placement & Structural Context**: Icons appear in predictable locations across UI layouts:
    -   *App Bars & Toolbars*: Navigation cues (hamburger menu, back arrow) and global actions (magnifying glass search, three-dots overflow).
    -   *Buttons & Chips*: Embedded as leading or trailing visual anchors alongside text labels.
    -   *Lists & Tables*: Positioned in leading slots to indicate row functionality or trailing slots (chevrons) to indicate navigation.
-   **Mandatory Dual Mapping (Icon Graphic + Interactive Target)**: When analyzing screens featuring clickable icons, agents MUST NOT map the element solely to `Icon button`. Downstream evaluation systems assert the presence of underlying `Icon` components. Agents MUST explicitly output BOTH components as separate objects:
    -   **Standalone Icon Graphic (`Icon`) [MANDATORY]**: Exclusively bound the visual icon vector itself and classify it as `Icon` (category: `Primitives` or `Content`).
    -   **Interactive Target (`Icon button`)**: Bound the surrounding clickable touch target area or outer action container and classify it as `Icon button`.
    -   *Non-Clickable Icons*: If an icon is purely informational or decorative (e.g., a calendar graphic inside a card header, warning icon in a callout), classify it solely as `Icon`.

## Part 2: Elements GM3 Specifications & Compliance Auditing

When conducting an Elements GM3 adherence audit, evaluate detected icons against the following strict standards:

### Component Specifications & Sizing

Elements GM3 establishes specific guidelines for system and branded iconography:

1.  **Google Symbols (System Icons)**:
    -   **Upgrade from GM2**: Google Symbols replaces legacy static SVG Material Icons (GM2). Google Symbols is a variable font format, allowing custom parameter modifications: **weight, fill, optical size, grade, and roundedness**.
    -   **Visual Benefit**: Variable font icons automatically adjust stroke weights when users zoom screens in or out, enhancing accessibility.
    -   **Style Guideline**: **Use filled icons as default** (if available). Outlined icons are used for inactive, untoggled, or supplementary states.
    -   **Sizing Range**: Standard interactive icons are typically 24dp (can use optical size range from 20dp to 48dp). Touch target must be at least 48x48dp.
2.  **AI Iconography**:
    -   **AI Feature Icons**: Used in buttons for specific actions or paired with card titles for content generated by AI. These system icons feature a **single spark** to visually signal generative AI capabilities, building user trust.
    -   **Standalone Spark Icon**: Used for generative AI outputs where standard AI feature icons are too visually complex or lack sufficient visual weight.
    -   **Gemini Product Icon (Full Color Spark)**: Reserved exclusively for approved Gemini products. It must **not** be used in general CE products. Sparks must not be added to existing product icons. If a product has significant AI capabilities, use a "Powered by AI" product badge instead.
3.  **Active/Toggle States**:
    -   Toggles use a **filled icon** for the active state and **outlined icons** for the inactive state.
    -   If an icon doesn’t have a filled style, change the icon font weight to **semibold** upon selection.
    -   Active states can optionally incorporate a background shape colored with the `secondary-container` color as an additional visual cue.
4.  **Decorative Icons & Contrast**:
    -   Used in non-interactive empty states, callouts, or illustrations.
    -   **Contrast Ratios**:
        -   Icons with either dimension **less than 20px** must have a contrast ratio of at least **4.5:1**.
        -   Icons with both dimensions **greater than 20px** must have a contrast ratio of at least **3:1**.
5.  **Accessibility & Annotations**:
    -   **Interactive Icons**: Must have clear and concise accessibility labels describing their purpose or behavior.
    -   **Decorative Icons**: When an icon appears alongside equivalent visible text or does not add meaningful information, it must be marked as 'decorative' (e.g., `aria-hidden="true"`) to prevent verbalization by screen readers.
    -   **Navigation Pairing**: Icons used for navigation (such as rail or drawer items) must be paired with clear visible labels to ensure legibility.

### Critical Elements GM3 Violations to Flag

-   **Color-Only Toggles**: Indicating toggle selections solely via color changes without altering icon fill or switching weight to semibold.
-   **Improper AI Branding**: Using custom stars, multi-colored sparks, or adding sparks directly onto existing product icons in general CE products.
-   **Missing Dual Mapping**: Failing to extract the standalone `Icon` graphic as a separate element from its interactive `Icon button` container during audits.
-   **Low Contrast on Decorative Icons**: Applying decorative icons on colored backgrounds that fail WCAG/GAR contrast minimums (4.5:1 for <20px, 3:1 for >=20px).
